These variables change how tools run.
They set Bash time limits and output size, shell choice, search behavior, permission helpers, and the sandbox.
Use them when long commands reach their time limit or when you need to limit what a tool can see.

This page lists 105 variables. `BASH_DEFAULT_TIMEOUT_MS` and `BASH_MAX_OUTPUT_LENGTH` are common. Switch rows take `1` or `0`.

## Example

```json title="~/.claude/settings.json"
{
  "$schema": "https://clawdipedia.cc/schemas/claude-code-settings.json",
  "env": {
    "BASH_DEFAULT_TIMEOUT_MS": "300000",
    "BASH_MAX_OUTPUT_LENGTH": "60000"
  }
}
```

A Bash call now waits up to five minutes before it reaches its timeout.

## How It Works

The Bash tool starts a shell for each command. Claude Code reads many variables here when the command starts.
Some variables also pass into the child shell, so a tool you run sees them too.
`CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` strips credentials from the environment of subprocesses such as Bash, hooks, and stdio MCP servers.

## What the Scrub Removes

We read the lists in the program and ran a Bash call with the scrub on (see [Probes](../../reference/probes.md#static-and-print-probes)). The scrub removes these from the subprocess environment:

- About 95 fixed credential names, such as `ANTHROPIC_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_AUTH_TOKEN`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`, `GOOGLE_APPLICATION_CREDENTIALS`, `AZURE_CLIENT_SECRET`, `HF_TOKEN`, `NODE_AUTH_TOKEN`, `CARGO_REGISTRY_TOKEN`, `VAULT_TOKEN`, `SLACK_WEBHOOK_URL`, and `ACTIONS_RUNTIME_TOKEN`. The scrub also removes the same names with an `INPUT_` prefix.
- About 90 path and config names, such as `AWS_SHARED_CREDENTIALS_FILE`, `KUBECONFIG`, `NETRC`, `DOCKER_CONFIG`, `GH_CONFIG_DIR`, `GNUPGHOME`, `SSH_AUTH_SOCK`, `GIT_ASKPASS`, `XDG_CONFIG_HOME`, `GIT_CONFIG_GLOBAL`, and `CLAUDE_CONFIG_DIR`.
- Any name that has a word such as `TOKEN`, `SECRET`, `PASSWORD`, `KEY`, `AUTH`, `COOKIE`, `PAT`, `DSN`, `WEBHOOK`, or `CREDENTIAL`, and any variable whose value has credentials in a URL, such as `DATABASE_URL`.

The four GitHub token variables (`GH_TOKEN`, `GITHUB_TOKEN`, `GH_ENTERPRISE_TOKEN`, `GITHUB_ENTERPRISE_TOKEN`) are the exception. In our run, a Bash child still saw them. It also saw `GH_HOST` and `HTTPS_PROXY`.

While the scrub is on (`CLAUDE_CODE_SUBPROCESS_ENV_SCRUB` true, or `GITHUB_ACTIONS` true and the scrub not set to `0`), Claude Code forces the permission mode to `default`. The message says: "Permission mode forced to default - CLAUDE_CODE_SUBPROCESS_ENV_SCRUB is set (allowed_non_write_users hardening). Declare allowedTools explicitly, or set CLAUDE_CODE_SUBPROCESS_ENV_SCRUB=0 to opt out." In `-p`, `--permission-mode bypassPermissions` still asked for approval for `Bash` until we passed `--allowedTools`.
