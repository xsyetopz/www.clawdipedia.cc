# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

The site documents Claude Code `2.1.327`, the only release it tracks. The version of the site itself is set in `package.json`, and the tracked Claude Code version is set in `src/version.ts`.

## [Unreleased]

### Added

- A manual fixture can hold an `unsent` map: the types of fields that the program builds but never writes or sends, which the schema leaves out. `claude-code-otel.json` types the attributes of the four spans that `2.1.327` never starts (`bash.subprocess`, `compaction`, `mcp.rpc`, `subagent.spawn`: their creators return first through `function XXe(){return!1}`, chunk-epqcnh2q.js:8867). Each span has 8 base attributes from `Mt()` (chunk-epqcnh2q.js:9452), `gen_ai.provider.name` from `Wt()` (chunk-epqcnh2q.js:9054), and its own attributes read from its creation site, such as `shell.type` (`bash` or `powershell`) and `trigger` (`auto` or `manual`): 55 entries. `claude-code-transcript.json` types the 23 `progress.data` fields of the REPL tool's `repl_tool_call` progress lines and `system.plugin` and `system.id` of the `placed` system line, which the transcript writer drops. The audit marks a gone field `removed` only when its `unsent` entry has live anchors; otherwise it fails with `no entry` or `anchor gone`. `bun run schemas` reports an `unsent` entry as stale when its anchor is gone or the schema has its path again.

- Print-mode observe cases in `tools/schemas/observe/print/cases-otel.ts` sample the OpenTelemetry sites that the other cases do not reach: `otel-hook-span`, `otel-pull-request-count`, `otel-permission-mode`, `otel-safety-deny`, `otel-safety-hook`, `otel-internal-error`, `otel-hook-plugin-metrics`, and `otel-retention-sweep`. A case `env` value can use `{COLLECTOR}` for the URL of the local collector.
- An `otel` PTY group in `tools/release/probes/pty/otel.ts` samples the events that only the interactive session sends: `otel.auth-logout`, `otel.feedback-survey`, and `otel.plugin-installed`. Each case runs the print-mode collector as a mock (`tools/schemas/observe/print/otel-mock.ts`) and keeps the value-free field types as `<case>.fields.json`.
- cc-inspect `0.18.4`: the `sessions` tool has a `fields` action. It lists the JSON types at each key path of the matched transcript lines and keeps no value.
- A `transcript` PTY group in `tools/release/probes/pty/transcript.ts`. Its `transcript.loop-noop-fold` case samples `system.foldedUuids`, `system.noOpStreak`, and `system.streakStartedAt`, and keeps the value-free field types of each transcript as `<case>.fields.json`.
- The PTY cases `transcript.memory-recall-cut` and `transcript.memory-recall-cut-address` resume a session that has an account memory recall and sample `api-request.cut` in the interactive session. The second case also samples `api-request.cut.markAddresses` through a mock claude.ai connector list (`tools/release/lib/stub/connector.ts`). A PTY case can now run a `mock` server for the length of the run. The TLS server and proxy of the Remote Control mock are now shared in `tools/release/lib/stub/tls-proxy.ts`.
- The print-mode case `compact-artifact-carry` samples `system.compactMetadata.preCompactArtifactReadVersions`.
- Print-mode observe cases in `tools/schemas/observe/print/` that make the program write the transcript fields that were typed from code only: data-flow records, `derived-from`, `session-owner`, `resume-head-vouch`, `api-request.cut` (with `messages`), `api-request.withheld`, `toolDenialFromHost`, the items of hook, sandbox, plan-snapshot, and shell hand-off arrays, interrupted and denied tool calls, mod hooks, and more. The cases are split by kind: `cases-replies.ts`, `cases-mods.ts`, `cases-gated.ts`, `cases-resume.ts`, `cases-cut.ts`, `cases-items.ts`, and `cases-host.ts`. A case can set its own `timeoutMs`. `bun tools/schemas/observe/print.ts OUT --only ID,ID --keep DIR` runs only the named cases and keeps a copy of each sandbox.
- The local model stub takes a list of `turns` (one reply for each request), `rules` (a reply for a request whose body has a given text, with `once`), and an `open` stream that it does not close. A case can also send paced stream-JSON input (a number waits that many milliseconds), merge keys into `.claude.json`, make a first Git commit, and run with no API key (`noKey`) to read a made-up login file.

It announces one tool host and answers each remote tool call with the disposition a case picks. The stub also takes `countTokens`, the `input_tokens` that `count_tokens` answers.

### Changed

- The OpenTelemetry schema leaves out the four spans that `2.1.327` never sends: `claude_code.bash.subprocess`, `claude_code.compaction`, `claude_code.mcp.rpc`, and `claude_code.subagent.spawn`. The generator (`tools/schemas/code/otel-gate.ts`) drops a span when the function that starts it returns at once through a gate that always returns `false`. The OpenTelemetry page lists them under Spans That Are Never Sent.
- The transcript schema no longer lists `attachment.attachment.hooks`. Only the display builds the `async_hook_response_batch` and `teammate_shutdown_batch` attachments (the program, chunk-a2xjwn0h.js:168458 at `2.1.327`), and the transcript write-site check now counts them as not kept.
- The note of `api-request.renderedWithdrawn` states why `2.1.327` cannot write it (the program, chunk-m14bt1pz.js:3987339 at `2.1.327`).
- The transcript schema no longer lists the `data` fields of `progress` lines: in `2.1.327` the writer drops each `progress` line before it writes it. The Transcript Format page says so, and the transcript write-site check counts `progress` as a type that the program does not keep.
- The transcript schema no longer takes keys from an object literal that sets `persist: false`. The transcript writer drops each such row before it writes the file (the program, chunk-m14bt1pz.js:696693 at `2.1.327`). Because of this, `system` no longer has `plugin`, `id`, or `persist`, which only the `placed` rows of plugins set (chunk-m14bt1pz.js:4839916).
